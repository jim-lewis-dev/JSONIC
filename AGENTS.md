# Working rules

- Maintain one current implementation. Do not add release numbers, numbered
  filenames, schema identifiers, migration code, or compatibility modes.
- Keep Git local. Do not add a remote or push anything.
- JSONIC stands for JavaScript Object Notation with Integrated Comments.
- Use ./export.py to obtain the user's current files and Git state before
  preparing changes that depend on unseen local edits. Preserve those edits.
- Deliver requested changes as JSONIC.zip with complete replacement files and
  update.json containing a plainspoken commit message and explicit removals.
  No numbered archive names. Run ./update.py inside the project to apply it,
  commit locally, and remove the download after success. The user tests after
  the commit. Refuse updates when any nonignored staged, unstaged, or untracked
  work exists, including unrelated files. Never checkpoint, stash, or reset
  that work automatically.
- Keep update.py and export.py executable inside this project; no home-directory
  wrappers, symlinks, or legacy command files. update.py defaults to its own
  project and ~/Downloads/JSONIC.zip. export.py defaults to its own project
  and PROJECT/JSONIC-snapshot.zip, which Git ignores. Export can capture dirty
  work without changing Git or the project files. Preserve useful ignored
  configuration/style files; exclude the snapshot itself and generated caches.
- Preserve the existing byte-oriented parser and exact data-token spellings.
  Do not introduce third-party dependencies or a second processing pipeline.
- Array styling is strictly positional, exactly as object styling is keyed.
  Ignore absent positions and keys. Do not move orphaned comments to the end,
  follow values, repeat the last style, or infer new comments/indentation.
- Successful capture always replaces the previous style, including with {}.
- Keep --raw, --mini, and --minified as aliases. --strip removes comments
  while preserving outside whitespace and all line endings.
- --pretty emits comment-free JSON with two-space indentation, LF line endings,
  and a final newline. Keep tokens and key order unchanged; do not capture style.
- Accept strict UTF-8 JSON in .json files, and JSON plus the supported comment
  forms in .jsonic files. Require unique object keys. Invalid input gets an
  explicit error, nonzero exit, and no partial output.
- Keep //, /* ... */, and triple-single-quote comments. Blocks do not nest.
- Preserve existing POSIX mode bits, respect umask for new files, and follow
  output symlinks while keeping atomic replacement. Do not claim full metadata
  preservation (owner/group/ACL/xattrs/hardlinks).
- Style files are captures generated by this tool. Deliberately damaged styles
  are not a product use case; do not build a separate hardening framework.
- Keep tests practical: exact output, real edits, all supported comment forms,
  strings that resemble comments, data-token preservation, and CLI failures.
- Run: python3 -m unittest discover -s tests -v
- Keep explanations short. No backup directories or generated test outputs
  belong in the project.
